装好 CC 只是开始，怎么把它用顺手是另一回事。这篇跳过安装（去看 [上一篇](https://blog.mistfly.xyz/posts/claude-code-setup/)），直接讲 CC 的功能和用法。

# 工作模式

CC 不是一启动就闷头干活的工具，它有三种工作模式，各有分工。

| 模式                  | 干什么的                                                                              |
| --------------------- | ------------------------------------------------------------------------------------- |
| **默认模式**          | 刚启动就是这个状态。你可以跟 CC 聊天、问问题、查资料，就是一个增强版的对话框。        |
| **计划模式**          | 遇到复杂任务，CC 会自动切到这里。它会分析需求、拆解步骤，但不会动你的代码，纯做规划。 |
| **Accept Edits 模式** | 方案确认后切到这里，CC 才会真正开始改代码、写文件。                                   |

三种模式之间用 `Shift + Tab` 切换。


### 怎么选

- **问问题、查资料、闲聊** → 默认模式就够了
- **改代码、写功能** → 先进计划模式让 CC 规划，你确认方案后再切到 Accept Edits
- **小改动、快速修 bug** → 直接切 Accept Edits，省掉规划环节

### 免确认模式（慎用）

退出 CC 后用这个命令重启，它会跳过所有权限确认，直接执行操作：

```bash
claude --dangerously-skip-permissions
```

适合你自己一个人开发、对操作有完全把握的时候。**生产环境或者不确定的操作，千万别开。**

### 终端命令确认

在 Accept Edits 模式下执行终端命令时，CC 会弹出三个选项让你确认：

![终端命令确认](https://img.mistfly.xyz/file/blog/7oPv6TcM.png)

- **仅同意这一次** — 只放行这一条，下次还得确认
- **同意并记住** — 这次放行，以后同类命令也不再问，省心
- **不同意** — 拒绝执行，CC 会换方案

一般来说，安装依赖这种明确无害的命令选"同意并记住"，其他不确定的就选"仅同意这一次"。

# 指令大全

指令是 CC 的主要操作方式。对话框里输入 `/` 就能看到完整列表，这里挑重点讲。

| 指令          | 用途                                           |
| ------------- | ---------------------------------------------- |
| `/compact`    | 手动压缩上下文，释放空间                       |
| `/clear`      | 清空上下文，等于开新会话                       |
| `/context`    | 查看当前上下文占用情况                         |
| `/resume`     | 恢复之前的对话                                 |
| `/init`       | 生成项目级 `Claude.md` 配置文件                |
| `/memory`     | 管理全局/项目记忆和 Auto Memory                |
| `/btw + 任务` | 临时隔离上下文干点别的，完事 `Esc` 回来        |
| `/simplify`   | 代码审查，从质量、性能、复用性三个维度自动优化 |
| `/rewind`     | 回滚操作（连按两下 `Esc` 也能回滚）            |
| `/model`      | 切换模型（用了 CC Switch 的话这条用不上）      |
| `/skills`     | 管理已下载的技能                               |
| `/mcp`        | 管理 MCP 服务器                                |
| `/hooks`      | 查看和配置事件钩子                             |
| `/agents`     | 创建和管理子 Agent                             |
| `/plugin`     | 安装和管理插件                                 |
| `/help`       | 查看所有指令的完整说明                         |

### 重点指令详解

**`/compact` — 上下文压缩**

上下文快满的时候用。可以不带参数直接压缩，也可以带上提示词告诉 CC 哪些内容要保留：

```bash
/compact
```

```bash
/compact 保留关于登录模块的所有设计决策和代码修改
```

**`/btw` — 临时对话**

这个特别好用。比如你正在改项目 A，突然想问个无关的问题，用 `/btw` 隔离上下文，完事按 `Esc` 回来继续，不会污染主会话。

```bash
/btw 帮我解释一下 JavaScript 的事件循环机制
```

**`/simplify` — 代码审查**

让 CC 从质量、性能、复用性三个维度审查你的代码，审查完自动优化修改。适合写完一段代码后让 CC 帮你"体检"一下。

**`/rewind` — 回滚**

改错代码了？连按两下 `Esc` 或者输入 `/rewind` 就能回到之前的状态，比手动 `git` 恢复方便。

# 上下文管理

上下文是 CC 的"短期记忆"，容量有限，需要你主动管理。

CC 每次对话都会把之前的聊天记录塞进上下文窗口。用着用着空间越来越满，CC 会变慢，甚至"断片"——你明明说过的需求它不记得了。

## 查看上下文

随时输入 `/context` 看看当前状态：

```bash
/context
```

![查看上下文](https://img.mistfly.xyz/file/blog/2ETE3yED.png)

主要看这几个数字：

| 信息            | 含义                                   |
| --------------- | -------------------------------------- |
| **总 token 数** | 当前使用量 / 上限（比如 77.8k / 200k） |
| **占用百分比**  | 一眼看出还能聊多久                     |
| **消息占比**    | 越大说明聊天记录越长，离压缩越近       |

## 什么时候该压缩

别等 CC 提醒你，这几个信号出现就该动手：

- **占用超过 60%** — 最直观的指标
- **CC 响应变慢** — 以前秒回现在等半天
- **CC 开始"断片"** — 说过的需求它不记得了
- **完成阶段性任务** — 刚做完一个功能模块，趁这个节点压缩
- **切换工作方向** — 从修 bug 改成写新功能，压缩一下让 CC 重新聚焦

## 压缩上下文

用 `/compact` 手动压缩：

```bash
/compact
```

压缩的时候带上提示词，告诉 CC 哪些信息要保留：

```bash
/compact 重点保留数据库表结构相关的讨论，其他可以精简
```

建议的压缩时机：

- **60% 左右** — 轻度压缩，影响最小
- **75% 左右** — 必须压缩，否则可能丢信息
- **90% 以上** — 赶紧压缩，否则 CC 可能无法正常工作

## 清空上下文

如果会话实在太乱，不如推倒重来：

```bash
/clear
```

什么时候用 `/clear`：

- 会话太长，压缩也救不回来
- 之前的上下文跟当前任务完全无关
- CC 行为变得很奇怪，需要重置状态
- 换了一个完全不同的开发任务

清空前注意：之前的对话记录就没了，重要的设计决策记得提前写进 `Claude.md` 或记忆。

## 对话恢复

不小心关了窗口或者切了项目，想找回之前的对话？用 `/resume`：

```bash
/resume
```

![对话恢复](https://img.mistfly.xyz/file/blog/FpAIcKTW.png)

它会列出你之前的会话记录，选一个就能接着聊，上下文完整保留。

## 状态栏常驻显示

每次手动输 `/context` 太麻烦？可以让上下文占用情况常驻在状态栏。输入以下提示词，按 CC 引导完成后重启终端：

```bash
帮我配一个 statusLine, 显示当前目录 + 模型 + 上下文剩余百分比（进度条显示）
```

![状态栏常驻显示](https://img.mistfly.xyz/file/blog/V5GykO71.png)

配好后终端底部会一直显示当前目录、模型名称和上下文进度条，一眼就能看到。

## 多会话管理技巧

- **按任务拆分会话** — 一个会话专注做一件事，做完就开新的
- **善用 `/btw`** — 临时有别的事，用 `/btw` 隔离，完事 `Esc` 回来
- **重要决策及时记录** — 写进 `Claude.md` 或记忆，清空上下文也不会丢
- **阶段性压缩** — 完成一个功能模块就压缩一次，保持上下文"年轻"

# Claude.md 配置

`Claude.md` 是 CC 的"项目说明书"。CC 启动时会自动读取，里面的内容直接影响它的行为。

你写"永远用中文回复"，CC 就一直说中文；你写"写代码时加注释"，它就乖乖加注释。

## 项目级 Claude.md

在项目根目录下生成一份，CC 自动读取：

```bash
/init
```

项目级配置只对当前项目生效，适合放项目相关的技术栈说明、代码规范、API 端点这些。

## 全局级 Claude.md

全局配置影响所有项目，适合放通用偏好。

**方式一：直接跟 CC 说**

```bash
回答时永远说中文，写进全局claude.md
```

**方式二：通过指令编辑**

输入 `/memory`，选择「User Memory」进入编辑界面：

![memory编辑](https://img.mistfly.xyz/file/blog/RhgQ42wD.png)

### 常用偏好示例

不知道该写什么？这几个可以直接抄：

**语言偏好**

```bash
回答时永远说中文，写进全局claude.md
```

**回复风格**

```bash
回复要简洁，不要废话，直接给结论和代码，写进全局claude.md
```

**Git 提交**

```bash
提交代码时使用中文 commit message，格式为"类型: 简短描述"，写进全局claude.md
```

### 加载机制

CC 启动时会按顺序加载配置：

1. **全局级** — 所有项目通用的偏好
2. **项目级** — 当前项目的特定配置
3. **目录级** — 当前目录下的配置（如果有的话）

后面的会覆盖前面的，所以你可以在全局层设"用中文"，但在某个英文项目里设"用英文"。

# Auto Memory

Auto Memory 是 CC 的自动记忆功能。开启后，它会在你工作过程中自动记下你的习惯、踩过的坑和积累的经验。

## 记什么

- 你纠正过 CC 的错误做法
- 你喜欢的代码风格和回复方式
- 项目中的特殊约定和坑
- 你反复强调的需求

## 什么时候生效

- 你告诉 CC "不要这样做"，它会记住下次不犯
- 你确认了某个方案可行，它会记住这个偏好
- 你踩过一个坑，它会记录下来避免重复

## 怎么开启

输入 `/memory`，选择「Auto-memory」然后回车：

![Auto-memory](https://img.mistfly.xyz/file/blog/2k8mMwl3.png)

## 注意事项

- 记忆只对当前项目生效，不会跨项目串台
- 可以通过 `/memory` 查看和管理已有记忆
- 记忆过时了可以手动删除或更新

# 能力扩展（进阶）

CC 本体功能已经够用了，但扩展生态才是它真正有意思的地方。

## Skill 技能扩展

Skill 是 CC 的技能包，装上之后能解锁新能力。比如 CC 本来不会设计前端界面，装上 Frontend-Design 技能后就能做 UI 了。

### 推荐 Skill

把 GitHub 链接发给 CC，它会帮你装好：

| 技能            | 作用                               | 来源                                                                            |
| --------------- | ---------------------------------- | ------------------------------------------------------------------------------- |
| Find-Skill      | 搜索和安装社区技能，相当于技能商店 | [GitHub](https://github.com/vercel-labs/skills/tree/main/skills/find-skills)    |
| Frontend-Design | 前端界面设计专家                   | [GitHub](https://github.com/anthropics/skills/tree/main/skills/frontend-design) |
| Skill-Creator   | 自己动手造技能                     | [GitHub](https://github.com/anthropics/skills/tree/main/skills/skill-creator)   |

### 手动安装

也可以去这些网站自己找技能手动装：

- [skills.sh](https://www.skills.sh/) — Skill 搜索和分享平台
- [LobeHub Skills](https://lobehub.com/zh/skills) — 按分类浏览，有精选合集

下载后放到对应目录就行：

- **全局级**：`~/.claude/skills/`
- **项目级**：项目根目录的 `.claude/skills/`

## MCP 扩展

MCP（Model Context Protocol）是 CC 连接外部工具的协议。装上 MCP 服务器后，CC 就能直接操作数据库、调 API、操作文件系统。

- 连接数据库，直接执行 SQL 查询
- 调用第三方 API（天气、翻译、新闻等）
- 操作文件系统（批量重命名、格式转换）
- 连接 Slack、飞书等通讯工具

## 子 Agent

子 Agent 是 CC 的分身，可以让多个 Agent 并行干活。

**为什么要用：**

- 一个 Agent 改前端，另一个改后端，同时进行
- 每个 Agent 专注一件事，减少上下文污染
- 子 Agent 有独立上下文，不会互相干扰

**怎么触发：**

- **自动触发** — 任务复杂、有并行可能时，CC 自己派生
- **手动创建** — 用 `/agents` 指令，进入 Library 界面搭建

**创建流程：**

1. 选择创建范围（项目级/全局级）
2. 选择「AI 辅助创建」
3. 描述这个子 Agent 要干啥（越具体越好）
4. 分配工具权限
5. 选模型（Sonnet 就够用）
6. 选个颜色跟主 Agent 区分

## Hook 钩子

Hook 是触发器，特定事件发生时自动跑脚本。比如改完代码后自动格式化，提交前自动检查安全问题。

**实用 Hook 示例：**

| 场景         | 提示词                                                |
| ------------ | ----------------------------------------------------- |
| 任务完成提醒 | 设置一个 hook，完成任务后自动发出"叮"的提示音         |
| 自动格式化   | 设置一个 hook，修改文件后自动运行 prettier 格式化代码 |
| 提交前检查   | 设置一个 hook，提交代码前自动检查格式和安全问题       |
| 防泄露       | 设置一个 hook，提交前检查有没有密码、密钥等敏感信息   |

**触发时机：**

- **PreToolUse** — 工具执行前触发
- **PostToolUse** — 工具执行后触发
- **Notification** — 通知时触发

## 插件

插件是"全家桶"，一个插件可能打包了 Skill + SubAgent + Hook + MCP。

通过 `/plugin` 进入插件商店安装。目前推荐：

| 插件            | 作用             | 来源                                                                                  |
| --------------- | ---------------- | ------------------------------------------------------------------------------------- |
| commit-commands | Git 操作一键搞定 | [GitHub](https://github.com/anthropics/claude-code/tree/main/plugins/commit-commands) |

# 实用技巧

最后说几个实用技巧。

## 别把所有事塞一个会话

上下文有限，一个会话专注做一件事，做完就开新的。把"重构登录模块"和"写支付功能"塞一个会话里，上下文乱了 CC 容易出错。

## 重要决策写进 Claude.md

代码规范、技术选型、架构决策这些长期有效的信息，写进 `Claude.md`，清空上下文也不会丢。

## 善用 Shift + Tab

`Shift + Tab` 切换模式是高频操作。问问题用默认，规划用计划模式，动手用 Accept Edits。

## 用 /btw 隔离临时问题

正在改代码突然想问个无关的问题，用 `/btw` 隔离上下文，完事 `Esc` 回来就行。

## 不确定的操作选"仅同意一次"

装依赖、跑测试这种无害的命令可以"同意并记住"，改配置、删文件这种有风险的操作还是每次确认一下。
